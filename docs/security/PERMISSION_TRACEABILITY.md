### Conflicting

- `POS_TENDER_EXTERNAL_CONFIRM` conflicts with `POS_TENDER_EXTERNAL_RECORD`: SRS §11.2 names an external-confirm permission, while the implemented POS API records an external tender attempt with POS_TENDER_EXTERNAL_RECORD and requires separate POS_TENDER_MANUAL_VERIFY for review. ## Actor and resource constraints

Permission grants do not replace scope checks. Tenant membership, branch assignment, register assignment, cashier/session ownership, original order/payment ownership, and object lifecycle checks remain additional backend controls. `/api/v1/auth/me` returns the current actor context's effective, active permission set; platform, vendor and customer contexts are not combined.

## Verification state

The traceability rows identify current endpoints, services, UI operations and test references. Runtime proof is accepted only from the corresponding test's execution on the final commit. P1-01/P1-02 and P0-06 regression suites, both database suites and frontend build must pass on the same final branch head before P1-03 can be marked COMPLETE.
